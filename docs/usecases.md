# Сценарии использования (Use Cases)

## 1. Регистрация нового клиента
**Актор:** Гость
**Цель:** Создать аккаунт для возможности оставлять заявки на услуги.
**Основной сценарий:**
1. Гость открывает `index.php` и нажимает «Регистрация».
2. Заполняет форму: логин, пароль, ФИО, телефон, email.
3. Нажимает «Отправить».
4. Система проверяет валидацию (латиница, длина, формат).
5. Система хеширует пароль и сохраняет пользователя в БД.
6. Редирект на `login.php` с сообщением «Регистрация успешна».

**Альтернативные сценарии:**
*   *Логин занят:* Система выводит ошибку «Логин уже существует», форма сохраняет введенные данные.
*   *Ошибка валидации:* Неверный формат телефона или ФИО. Выводится сообщение, форма подсвечивает ошибки.

## 2. Создание заявки на услугу
**Актор:** Клиент
**Цель:** Заказать бытовую услугу.
**Основной сценарий:**
1. Клиент авторизован, находится на `orders.php`.
2. Нажимает «Новая заявка» (`order_new.php`).
3. Выбирает вид услуги, описывает задачу, выбирает «Самовывоз» или вводит адрес, указывает желаемую дату.
4. Нажимает «Отправить».
5. Система проверяет поля и сохраняет заявку в БД со статусом «Диагностика».
6. Редирект на `orders.php`, где отображается новая заявка.

**Альтернативные сценарии:**
*   *Выбрано «Другое»:* Появляется поле для текстового описания услуги.
*   *Выбран «Самовывоз»:* Поле «Адрес» не требует заполнения.

## 3. Обработка заявки администратором
**Актор:** Мастер-администратор
**Цель:** Обновить статус заявки и указать стоимость.
**Основной сценарий:**
1. Админ входит под `adminka`/`password`, попадает на `admin.php`.
2. Видит таблицу всех заявок.
3. Находит нужную заявку, меняет статус на «В ремонте».
4. Вводит стоимость услуги.
5. Нажимает «Сохранить». Данные обновляются в БД.
6. Клиент при следующем заходе видит новый статус и цену.

**Альтернативные сценарии:**
*   *Статус «Отклонено»:* Админ обязан заполнить поле «Причина отклонения». Если не заполнено — система выдает ошибку.
